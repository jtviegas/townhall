# Contributing to Townhall

First off, thank you for taking the time to contribute! We want to make contributing to Townhall as easy and transparent as possible, whether it's:

- Reporting a bug
- Discussing the current state of the code
- Submitting a fix
- Proposing new features

## Our Development Process

We use GitHub to manage reviews and pull requests.

1. **Fork the repo** and create your branch from `main`.
2. **If you've added code** that should be tested, add tests.
3. **If you've changed APIs**, update the documentation.
4. **Ensure the test suite passes**.
5. **Issue that pull request!**

## Instructions for AI Agents (Claude/Cursor/Copilot)

If you are an AI agent contributing to this repository:
- Follow the architectural patterns established in existing modules.
- Ensure all new functions include descriptive docstrings.
- Before submitting a PR, verify that your changes do not introduce linting errors.
- Clearly state in the PR description that the changes were generated or assisted by an agent.

## Pull Request Guidelines

- **Atomic Changes:** Keep your PRs focused. It is better to submit three small PRs than one massive one.
- **Commit Messages:** Use clear, descriptive commit messages (e.g., `feat: add user authentication` or `fix: resolve memory leak in worker`).
- **Branch Naming:** Use a prefix like `feature/`, `fix/`, or `docs/` (e.g., `feature/add-voting-system`).

## Bug Reports

We use GitHub issues to track public bugs. Please ensure your report includes:
- A quick summary and/or background.
- Steps to reproduce.
- What you expected would happen.
- What actually happens.
